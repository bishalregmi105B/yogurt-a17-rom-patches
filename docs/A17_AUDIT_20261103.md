## 4. Online research findings (mt6768 ecosystem, verified 2026-11-03)

### The reference port: mt6768-dev GitHub org (Redmi 9 family, SAME SoC + 4.14 kernel)
- **LineageOS 23 (Android 16) builds & runs** on Redmi 9A (lancelot) — XDA thread 4802880: everything works except RIL (untested, broken-IMEI test device). Trees: [mt6768-dev org](https://github.com/mt6768-dev).
- Their device tree has an **active lineage-24.0 branch** (Android 17, updated 2026-10-25) — 610 commits, structure: configs/, rootdir/, sepolicy/, blob-patches/, compatibility_matrix.xml, manifest.xml.
- **Kernel has lineage-24.0 branch too** (4.14, updated 2026-10-31) + a `perfmgr` branch (kernel-side perfmgr for libperfmgr powerhint.json).
- Their recipe matches ours where it matters: **FCM target-level=7** (identical to our session-4 decision), syscall backports per Android version (they: clone3; we: close_range/faccessat2/epoll_pwait2), ext4 super, AB_OTA_UPDATER=false, A-only.
- **Differences worth stealing**:
  1. They build the kernel with **clang r416183b** (clang 12) — newer toolchain than our r353983c (clang 9); potential Phase-3 hardening/perf item, not needed for boot.
  2. **vendor.security_patch = 2022-12-01** set in BoardConfig — sidesteps the SPL-downgrade sideload dance our recovery patch auto-approves. Candidate: set BOARD_VENDOR_SECURITY_PATCH forward in derp_yogurt.mk/BoardConfig to sideload SPL cleanly.
  3. **blob-patches** approach: smali patches to MTK IMS blobs (0001-ImsService export receivers for A12+ exported-receiver requirement; 0002-MtkRadioExImsIndication NtTelephony removal). If IMS breaks on A17 flash, this is the proven class of fix for our vendor blobs too.
  4. **AOSP PowerHAL via libperfmgr** (configs/powerhint.json with CPULittle/Big cluster freq nodes: A55 policy0 max 1.8 GHz ladder, A75 policy6 max 2.0 GHz ladder) instead of mtkpower blob HAL. Phase-3 option for DerpFest GameSpace integration; our current mtkpower@1.2 + powerscntbl.xml path is functional (landed 22:06 commit).
  5. **Camera pipeline-buffer props** (persist.vendor.camera3.pipeline.bufnum.{base,min_high_ram,min_low_ram}.{imgo,rrzo,lcso,rsso,fdyuv}=4-7, zsl.default=140, debug.stagefright.c2inputsurface=-1) — drop-in MTK mtkcam tuning for capture latency; candidate for our vendor.prop.
- Their VINTF: audio 7.0 / camera 2.6 + isphal 1.0 / keymaster 4.1 + mtk attestation 1.1 / radio 1.2+1.6 / sensors 2.0 / mtkpower 1.2 — useful as the expected HAL surface of an A11-era MTK vendor on A17; yogurt's A10 vendor sits one notch lower and rides our DEVICE_FRAMEWORK_COMPATIBILITY_MATRIX_FILE acks.
